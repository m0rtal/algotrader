# algotrader-api

Self-hosted algorithmic trading backend for MOEX.

## Stack

- Python 3.11+ with `uv` for dependency management
- FastAPI + Uvicorn
- DuckDB (analytical engine over parquet bars)
- SQLite (settings, signal/trade/portfolio state, WAL mode)
- OpenTelemetry → OTLP gRPC → Loki + Tempo + Grafana
- structlog for structured JSON logs

## Install

```bash
uv sync --extra dev
```

## Run dev

```bash
cp .env.example .env
uv run uvicorn algotrader_api.main:app --host 127.0.0.1 --port 8000 --reload
```

Service is at <http://127.0.0.1:8000>. OpenAPI docs at <http://127.0.0.1:8000/docs>.

## Run tests

```bash
uv run pytest --cov=algotrader_api --cov-report=term
```

Coverage gate: ≥95% on stmts / branches / funcs / lines.

## Endpoints

| Method | Path | Source |
|---|---|---|
| GET    | `/health`              | SQLite + DuckDB ping |
| GET    | `/api/settings`        | SQLite (or defaults) |
| PUT    | `/api/settings`        | SQLite + version check (409 on conflict) |
| DELETE | `/api/settings`        | Reset to defaults |
| GET    | `/api/bars/{symbol}`   | DuckDB over parquet |

## Observability

Every request emits:
- a `correlation_id` (UUID, returned in `X-Correlation-ID` response header)
- a structured JSON log event via structlog
- an OpenTelemetry span (HTTP root + child DB query spans)

Configure the OTLP endpoint via `OTEL_EXPORTER_OTLP_ENDPOINT` (default `http://localhost:4317`).

The full observability stack (collector + Loki + Tempo + Grafana) lives in `ops/otel-collector/`.

## Notes

- **No auth** — LAN-bind by default; CORS-whitelist the frontend origin.
- **No live Tinkoff data yet** — bars are deterministic synthetic data generated by `seed/synth.py` on first start. Replace with real ingestion in a follow-up change.
- **Settings store** mirrors the Zod schema in `packages/shared/src/index.ts`. Pydantic validation happens server-side; tokens are masked in logs and never serialized to responses.
